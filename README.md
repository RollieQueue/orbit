# Orbit

Локальная оболочка для агента, который работает с вашими проектами через Codex CLI, Claude Code, Ollama или совместимый API. Проекты, разговоры, память и навыки принадлежат Orbit и сохраняются при смене модели. Агент сам выбирает действия, создаёт специалистов, получает их результаты и отвечает вам, а панель агентов показывает дерево делегирования, ход работы и результат каждого участника. Память трёх уровней — чат, проект и общая — и сохранённые навыки переживают перезапуск и доступны следующим задачам.

Установка CLI и вход в аккаунты не входят в Windows-пакет Orbit. Подробности подключения и ограничения транспорта: [docs/providers.md](docs/providers.md).

История изменений по версиям: [docs/CHANGELOG.md](docs/CHANGELOG.md).

## Как пользоваться

1. Выполните `npm install` и `npm run build`, затем запустите `Orbit.cmd` (или `npm start`) — Orbit стартует прямо из папки репозитория. Отдельная папка `Orbit-standalone-*` нужна только для распространения (`npm run package:win`).
2. Добавьте локальную папку или клонируйте Git-репозиторий. Обычные папки поддерживаются без `git init`.
3. В настройках выберите подключённого провайдера. Для Codex/Claude используется вход в их собственный CLI. Поле модели можно оставить пустым, чтобы использовать настройки CLI.
4. Создайте чат задачи и разговаривайте с агентом. Он сам выбирает действия, создаёт специалистов, получает их результаты и отвечает вам.
5. Откройте панель агентов, чтобы увидеть дерево делегирования, ход работы и результат каждого участника. Переключение чата или проекта не прерывает задачу.

Браузерный `npm run dev` без Electron показывает интерфейс; запуск агентов и доступ к файлам требуют desktop-приложения.

Выбор модели, уровня мышления и доступа находится рядом с полем сообщения. Ask показывает запросы разрешения; Full access запускает задачу без подтверждений. Доступ наследуется всеми подагентами. Уровень мышления доступен для Codex и совместимого API.

## Подключение провайдеров

**Codex / Claude Code:** установите CLI и выполните вход в нём. Orbit проверяет доступность CLI и авторизацию, но не копирует учётные данные. Для нестандартного пути задайте `ORBIT_CODEX_COMMAND` или `ORBIT_CLAUDE_COMMAND`.

**Ollama:** запустите локальный сервер с уже установленной моделью. Выберите модель в Orbit или задайте `ORBIT_OLLAMA_MODEL`. Orbit самостоятельно не скачивает модели. Адрес сервера меняется через `ORBIT_OLLAMA_URL`.

**Совместимый API:** перед запуском Orbit задайте переменные среды, например в PowerShell:

```powershell
$env:ORBIT_OPENAI_BASE_URL = 'http://127.0.0.1:1234/v1'
$env:ORBIT_OPENAI_MODEL = 'your-model-id'
# ORBIT_OPENAI_API_KEY — только если сервер требует ключ.
npm start
```

Подробности транспорта, ограничений доступа и официальные источники: [docs/providers.md](docs/providers.md).

## Память и развитие

Память содержит факты, предпочтения и решения и делится на три уровня.

| Уровень | Что хранит | Как уходит |
|---|---|---|
| Чат | рабочие заметки одной задачи: ограничения, принятые решения, что осталось сделать | не используется 30 дней; чат удалён; или поднимается в проект, если чат к записи возвращался |
| Проект | проверенные знания об одной кодовой базе, общие для всех её чатов | вытесняется по ценности при заполнении (250 записей) |
| Общая | то, что верно во всех проектах: предпочтения, общие приёмы, оценки моделей | вытесняется по ценности при заполнении (200 записей) |

Память не разрастается. У каждого уровня есть лимит; ценность записи складывается из уверенности, свежести и числа использований, поэтому невостребованное вытесняется первым. Закреплённые и написанные вами записи не вытесняются и не перезаписываются агентами. Агент, повторно записавший то же самое, обновляет существующую запись, а не создаёт копию; после каждого завершённого запуска дубликаты объединяются, устаревшее удаляется. Оценки моделей ограничены 60 записями. Заметка, слово в слово совпавшая в двух и более проектах и не называющая ни один из них, переезжает в общую память; похожая, но отличающаяся, например, числом или названием инструмента, не переезжает.

В промпт попадает не вся память, а подборка: закреплённое, затем найденное по задаче (индекс BM25 с учётом словоформ русского и английского), затем самое ценное; остальное перечислено заголовками, полное содержимое агент получает через `memory_search`. Общая память отключается для проекта переключателем, и тогда проект не читает и не пишет ни общие заметки, ни общие навыки и не участвует в их пополнении.

Навык содержит название, назначение, условия применения и инструкции, которые агент загружает по необходимости. Агент находит подходящий навык по задаче, применяет его и сообщает результат (`worked`, `partial`, `failed`); замечание к неудаче сохраняется как «подводный камень» для следующего агента. После содержательного запуска (10 и более ходов) или запуска, где применялся навык, оркестратор один раз получает напоминание оценить применённые навыки и сохранить новый, если в работе появилась повторяемая процедура: например, поднять изолированную копию окружения в Linux. Навык, привязанный к проекту, остаётся в нём; независимый от проекта агент сохраняет как общий.

Например: «После исправления запомни, как здесь запускать проверки» или «Создай вспомогательный скрипт для этой проверки, проверь его и сохрани навык для следующих задач». Решение о сохранении принимает модель через инструменты, а записи можно просмотреть, закрепить и удалить в интерфейсе.

Это развитие через проверенные процедуры, скрипты и память. Автоматическое изменение ядра Orbit с самостоятельной установкой новой версии приложения пока не реализовано. Код самой оболочки можно подключить как обычный проект и изменять тем же агентом; новую сборку нужно запустить отдельно.

## Хранение и ограничения

Данные сохраняются в Electron `userData` (обычно `%APPDATA%/orbit-ide`):

- `workspace-state.json` — проекты, чаты и настройки;
- `memory.json` — память всех трёх уровней (чат, проект, общая);
- `capabilities.json` — навыки, их предыдущие версии и статистика применения;
- `run-history/` — агенты, действия, результаты запусков и файлы, которые каждый агент читал или менял;
- `project-index/` — индекс проектов (пересобирается при повреждении).

Сохраняются резервные копии JSON. Работавшие в момент аварийного завершения задачи при следующем запуске помечаются прерванными. Закрытие приложения останавливает процессы; после запуска продолжите задачу сообщением в сохранённом чате. Отдельного постоянно работающего фонового сервиса пока нет.

В режиме чтения файловые изменения и команды оболочки через инструменты Orbit запрещены. В режиме работы с проектом файловые инструменты ограничены его папкой и проверяют символические ссылки. Команды процессов имеют права пользователя ОС; рабочая папка сама по себе не является системной песочницей. Дополнительные ограничения Codex/Claude описаны в документации адаптеров. Разные чаты могут работать параллельно в одной папке, включая запись. Файлы общие: поручайте изменения разных участков. В одном чате одновременно выполняется один запуск; после остановки нужно дождаться завершения его процессов. Внутри одного роя агент должен разделять файлы между специалистами.

Поддерживаются шесть адаптеров: Codex, Claude Code, Antigravity, Cursor, Ollama и совместимый API. OpenCode не подключён. Качество планирования и делегирования зависит от выбранной модели. Финальный ответ модели не подменяет результат тестов: фактические команды и ошибки видны в журнале агента.

## Сборка и обновления

Отдельная сборка для работы не нужна. Главный процесс (`electron/*.mts`) Node выполняет прямо из исходников, а `npm run build` за доли секунды собирает только интерфейс окна в `dist/`. Поэтому:

- первый запуск: `npm install`, `npm run build`, затем `Orbit.cmd` или `npm start`;
- после правки `electron/`: перезапустите Orbit (`Orbit.cmd --relaunch` перезапускает работающий экземпляр за 1–2 с);
- после правки `src/`: `npm run build` и `Orbit.cmd --relaunch`, либо работайте через `npm run dev`, где интерфейс обновляется без перезапуска;
- цикл, который делают агенты сами: `npm run self-upgrade` (проверки → сборка интерфейса → перезапуск → файл здоровья → откат при неудаче);
- `npm run package:win` нужен только для дистрибутива в отдельной папке `Orbit-standalone-*`; для обновлений он не используется, а накопившиеся папки показывает и удаляет `npm run clean:bundles`.

## Разработка и проверки

```powershell
npm install
npm run build          # tsc --noEmit + vite build → dist/
npm start              # Orbit из репозитория (то же, что Orbit.cmd)
npm run dev            # Vite с HMR + Electron (ORBIT_DEV=1)
npm test
npm run smoke
npm run smoke:desktop
npm run verify
npm run self-upgrade
npm run clean:bundles
npm run package:win    # отдельный дистрибутив Orbit-standalone-*; цикл обновления его не вызывает
```

Приложение запускается прямо из папки репозитория: `Orbit.cmd` (и `npm start`) выполняет `node_moduleselectrondistelectron.exe <репозиторий>`, главный процесс берётся из `electron/`, интерфейс — из `dist/`, данные — из `%APPDATA%/orbit-ide`, как и раньше. Если нет `dist/index.html` или `node_modules/electron`, `Orbit.cmd` завершается с понятным сообщением. Аргументы передаются дальше: `Orbit.cmd --relaunch` просит уже работающий Orbit перезапуститься (обработчик `second-instance` в `electron/main.cjs` сохраняет состояние, останавливает запуски и вызывает `app.relaunch`), а если Orbit не запущен — просто запускает его. Тот же перезапуск доступен окну через `window.orbit.relaunch()`.

Тесты используют управляемые провайдеры и локальный HTTP-сервер; они не тратят квоту модели. Desktop-проверка запускает настоящий Electron, preload, IPC и runtime во временном профиле. `npm run package:win` по-прежнему собирает отдельную папку `Orbit-standalone-*` для распространения (внутри неё `Orbit.cmd` запускает `Orbit.exe`). `npm run clean:bundles` показывает накопившиеся `Orbit-standalone-*`, `release*` и `.orbit-partial-*` с размерами и ничего не удаляет; `npm run clean:bundles -- --yes` удаляет их, оставляя новейшую сборку (`--all` — и её).

IPC между окном и главным процессом описан одной таблицей в `electron/ipc-contract.cjs` (метод → канал → аргументы → тип результата, плюс push-события `runtime:event` и `quota:update`). Из неё генерируются `electron/preload.cjs` целиком и блок `OrbitBridge` в `src/vite-env.d.ts` (между маркерами `BEGIN/END generated`): после правки таблицы выполните `node scripts/gen-ipc-types.cjs` (`--check` только сообщает о расхождении); `tests/ipc-contract.test.cjs` падает, если сгенерированные файлы устарели. Обработчики каналов живут в `electron/ipc-handlers.cjs`; при старте `main.cjs` проверяет, что каждый канал таблицы имеет обработчик и наоборот.

Инструмент агентов `run_command` по умолчанию ждёт 600 с (`timeout_ms` от 20 мс до 3 600 с), поэтому цикл обновления или длинный прогон тестов, запущенный из чата, не обрывается.

## Самообновление

`npm run self-upgrade` — живой цикл: блокировка → typecheck (оба tsconfig) → `node --experimental-strip-types --test tests/*.test.cjs` → runtime smoke → `tests/main-load.test.cjs` → `dist/` сохраняется в `dist-prev/`, проверенные `electron/` и `src/` снимаются в `refs/orbit/self-upgrade/candidate` (новые файлы тоже; индекс git не трогается) → `vite build` → работающему Orbit посылается `--relaunch` (`electron.exe <репозиторий> --relaunch`, то же, что `Orbit.cmd --relaunch`; без работающего экземпляра он просто запускается) → ожидание до 15 с свежего `artifacts/self-upgrade-health.json`. Файл здоровья пишет новый процесс после `did-finish-load`, одного IPC-обращения через preload и появления интерфейса (`{ ok, pid, startedAt, commit, distMtime }`); при `did-fail-load`, аварии рендерера или исключении до готовности — `{ ok: false, error }`. Сборок `Orbit-standalone-*` и electron-builder в цикле нет.

Удачный запуск делает снимок `refs/orbit/self-upgrade/last-good`. Неудача (нет файла здоровья за 15 с или `ok: false`): процессы Orbit этого репозитория останавливаются, неудачные исходники сохраняются в `refs/orbit/self-upgrade/failed` и `artifacts/self-upgrade-failed.patch`, возвращаются `dist-prev/` и `electron/` + `src/` из `last-good` (файлы, созданные после снимка, не удаляются), Orbit запускается снова, отчёт получает `status: rolled-back`. Вернуть неудачную правку: `git restore --source=refs/orbit/self-upgrade/failed --worktree -- electron src`. Пока снимка `last-good` нет (его создаёт первый успешный цикл), откатывается только `dist/`.

Фаза перезапуска выполняется отдельным процессом-наблюдателем, отвязанным от дерева процессов вызывающей команды: когда обновление запускает агент внутри Orbit, перезапуск останавливает его команды, а проверка здоровья и откат должны это пережить. Отчёт с временем каждого шага: `artifacts/self-upgrade-last.json`; журнал наблюдателя: `artifacts/self-upgrade-watch.log`. Флаги: `--dry-run` (план и проверка инструментов: tsc, vite, `electron.exe`, git), `--no-relaunch` (проверить и собрать, не перезапускать), `--verify-only`, `--desktop` (добавить `smoke:desktop`), `--force` (проверить и пересобрать, даже если исходники не менялись). Если исходники не менялись с последней проверенной сборки (`dist/orbit-build.json`) и работающий Orbit её использует — `status: up-to-date`; если не менялись, но Orbit не запущен или работает со старой сборкой — только перезапуск. Правка исходников во время проверок отменяет сборку (`dist/` возвращается из `dist-prev/`). Одновременно работает один цикл (`artifacts/self-upgrade.lock`); не больше `ORBIT_UPGRADE_MAX_CYCLES` (3) перезапусков за `ORBIT_UPGRADE_CYCLE_WINDOW_MIN` (30) минут; таймаут здоровья — `ORBIT_UPGRADE_HEALTH_TIMEOUT_MS`. Старые сборки код не удаляет — только `npm run clean:bundles -- --yes` по запросу.

Необязательная проверка с настоящей моделью: `node scripts/smoke-live.cjs`. Она использует текущий вход и модель Codex CLI, расходует квоту и проверяет создание одного подагента, ожидание результата и сохранение истории. Обычные тесты её не запускают.

Для проверки строгого протокола на `gpt-5.6-luna` с `xhigh`: `node scripts/smoke-protocol-live.cjs`. Проверка расходует квоту, запускает шесть помощников в пустой временной папке, проверяет их результаты и отсутствие ошибок протокола; отчёт сохраняется в `artifacts/protocol-live.json`.

Для проверки передачи управления при аудите проекта: `node scripts/smoke-handoff-live.cjs`. Она расходует квоту Luna/xhigh, разрешает чтение небольшого временного проекта и проверяет реальное создание восьми помощников, их результаты и параллельное выполнение. Отчёт: `artifacts/handoff-live.json`.

Для проверки сессионного режима на настоящем Claude Code: `node scripts/smoke-session-live.cjs [модель] [уровень]` (по умолчанию `haiku low`, тратит немного квоты). Агент с ограниченным доступом создаёт файл через инструмент Orbit по MCP одним процессом, затем корневой агент создаёт одного помощника, ждёт его и продолжает ту же сессию с результатом. Отчёт: `artifacts/session-live.json`.

Архитектура: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Идейные ориентиры: [Claudexor](https://github.com/razzant/claudexor) и [Ouroboros](https://github.com/razzant/ouroboros). Orbit — отдельная реализация; их движки не встроены.
