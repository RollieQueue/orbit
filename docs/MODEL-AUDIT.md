# Аудит моделей: кого звать под какую задачу

Замер 2026-09-30. Одно и то же задание решили 16 моделей из трёх подписок (Claude Code, Codex, Antigravity),
каждая в своей папке и без помощников. Ответы проверены по скрытому ключу: тесты, эталонные ответы, перебор.
Cursor проверить не удалось: у аккаунта исчерпан лимит бесплатного плана (подробнее в разделе «Cursor»).

## Кратко: кого звать

| Задача | Первый выбор | Другая подписка (запас, разгрузка квоты) | Не поручать |
|---|---|---|---|
| Оркестрация, план, итоговый ответ пользователю | Claude Opus 5.5 (Claude Code) | Claude Fable 5.1; GPT-6 Sol или Astra (Codex) | Haiku 4.5 |
| Написание кода по спецификации | Claude Sonnet 5.5 (Claude Code): 0,7–1 мин | GPT-6 Astra, GPT-6 Luna (Codex) | GPT-OSS 120B |
| Ревью кода, поиск ошибок, безопасность | GPT-6 Astra (Codex) вместе с Opus 5.5 или Fable 5.1 | Gemini 3.1 Pro (Antigravity) как независимое мнение | Haiku 4.5, Gemini 3.8 Flash, Claude 4.6 через Antigravity |
| Мелкие поручения: найти в коде, прочитать, простая правка, прогон тестов | GPT-6 Luna (Codex): 2 мин, без ошибок | GPT-5.6 Terra (Codex), Gemini 3.8 Flash (Antigravity) | Haiku 4.5 |
| Логика, перебор вариантов, расчёты | любой флагман: Opus 5.5, Fable 5.1, GPT-6 Sol или Astra, Gemini 3.1 Pro | Sonnet 5.5 | GPT-5.6 Luna, Haiku 4.5 |
| Тексты для пользователя на русском | Opus 5.5, Fable 5.1 | Gemini 3.1 Pro, Gemini 3.8 Flash | GPT-6 Luna, GPT-5.5, Haiku 4.5 |
| Кончилась квота Claude Code | Codex: GPT-6 Sol или Astra (по качеству на уровне Claude) | Antigravity: Gemini 3.1 Pro | GPT-OSS 120B |

Как разложить большую задачу по подпискам. Корневой агент — Opus 5.5. Реализацию делят Sonnet 5.5 и GPT-6 Astra
или Luna. Ревью — GPT-6 Astra плюс Gemini 3.1 Pro. Мелкие поиски — GPT-6 Luna. Тогда квота Claude Code уходит
только на оркестрацию и часть кода, а Codex и Antigravity работают параллельно.

Таблица записана в `electron/model-routing.json`. По ней Orbit выбирает модель помощника, когда агент называет тип
поручения (`spawn_agent` с `kind`: code, review, lookup, text) и не называет модель. Подписки без подключения или почти
без квоты он пропускает. Claude Fable 5.1 в файл не входит по просьбе пользователя от 2026-09-30: тратит гораздо
больше квоты и не лучше Opus 5.5. После нового замера правьте и этот файл.

## По подпискам

### Claude Code

- **Opus 5.5.** Всё верно, 1,6 мин, 7 вызовов инструментов. Нашёл все ошибки ревью, включая редкую гонку, и
  отметил ловушку в вопросе. За собой удалил черновые файлы. Лучший выбор для корневого агента.
- **Fable 5.1.** Всё верно, 2,7 мин, всего 5 вызовов. Самые подробные и точные объяснения. Годится как второй
  флагман и как замена Opus.
- **Sonnet 5.5.** Самый быстрый: 0,7–1,0 мин в трёх прогонах, код верный во всех трёх. Слабее Opus в деталях:
  в двух прогонах из трёх пропустил редкую гонку, один раз выдал сломанный JSON (вложил последние поля не туда).
  Лучший исполнитель кода, но структурированный ответ от него стоит проверять.
- **Haiku 4.5.** Худший из работающих. Сравнил комнаты через `localeCompare` вопреки спецификации («оператор <»),
  неверно посчитал варианты в логике (5 вместо 11), выдумал функцию `checkCycleLimit`, обернул JSON в ```,
  в тексте для пользователя оставил `git.exe` и не обратился на «вы». К тому же не быстрый: 5,5 мин и 32 вызова.

### Codex

- **GPT-6 Astra.** Всё верно, 1,8 мин. Самый дотошный: сверх задания сравнил своё решение с независимой
  реализацией на 2000 сгенерированных входах. Кроме настоящих ошибок сообщает и пограничные (нестрогий `parseInt`,
  символьные ссылки), так что ревью у него с запасом, но с шумом. Русский текст верный, но тяжеловат.
- **GPT-6 Sol.** Всё верно, 3,1 мин. Та же манера: плюс пара пограничных замечаний.
- **GPT-6 Luna.** Код, ревью, логика и репозиторий без ошибок за 2,0 мин — на уровне флагманов, хотя по названию
  «лёгкая». Текст на русском подвёл: 62 слова при лимите 60 и искажение смысла («Вы можете выполнить не более
  трёх автоматических перезапусков» — перезапуски делает Orbit, а не пользователь). Лучший дешёвый исполнитель
  технических поручений, но не автор текстов для пользователя.
- **GPT-5.6 Sol и Terra.** Технически без ошибок; в тексте потеряли условие «сверх лимита». Terra быстрее (2,4
  против 3,9 мин).
- **GPT-5.6 Luna.** Провалил логику: неверный порядок, 3 варианта вместо 11 и уверенное «допустимы два порядка».
  Для рассуждений не годится.
- **GPT-5.5.** Пропустил в ревью сбой записи (после него счётчики больше никогда не пишутся), в тексте нет «вы».
  Устаревшая модель, смысла звать её нет.

Общая черта Codex: модели сообщают больше пограничных находок (6 из 7 отметили нестрогий `parseInt`), а Claude и
Gemini — меньше, но только уверенные. Для ревью это удобно сочетать.

### Antigravity

- **Gemini 3.1 Pro.** Работает: региональной блокировки, записанной 2026-09-29, сейчас нет. Код, логика и
  репозиторий верно, хороший русский, чистый JSON; в ревью пропустил только редкую гонку. 4,1 мин. Лучший
  независимый рецензент из другого семейства моделей.
- **Gemini 3.8 Flash.** Тоже работает, 3,3 мин. Всё верно, кроме ревью: пропустил сбой записи и гонку.
  Годится для поиска и мелких правок, не для ревью.
- **Claude Opus 4.6 и Sonnet 4.6 (Thinking).** Код, логика и репозиторий верны, текст на русском хороший. Но
  они в 4–6 раз медленнее Claude Code (5,6–6,8 мин). В ревью оба пропустили гонку, а остановку записи после сбоя
  Opus не нашёл, Sonnet нашёл лишь частично. Итоговый ответ приходил вместе со всеми промежуточными рассуждениями:
  17–28 тыс. символов вместо 2–3 тыс., это засоряло контекст вызвавшего агента (исправлено, см. ниже пункт 1; Sonnet
  иногда пишет рассуждения и в последнем сообщении). Разумно звать только как запас, когда квота Claude Code исчерпана.
- **GPT-OSS 120B.** Прочитал три файла и 7 минут молчал. Вы отправили ему «стоп»; ход закончился фразой
  «I'm sorry about the error…», а на «стоп» он ответил, что прекратил работу. Задание не выполнено, для работы
  агентом модель не годится.

### Cursor

Агент Cursor Auto получил ответ `You've hit your usage limit`: лимит бесплатного плана исчерпан. Orbit сам
переключил его на Claude Sonnet 4.6 в Antigravity, отметил квоту Cursor исчерпанной, и Composer 2.5 и Grok 4.7
сразу ушли на Claude Sonnet 5.5, не обращаясь к Cursor. Эти прогоны засчитаны как повторы Sonnet, а не как
модели Cursor. Grok, Composer и остальной каталог Cursor остаются непроверенными; проверить их можно после сброса лимита
или на платном плане.

## Как проверяли

Задание одно для всех, на английском, ответ — строго один JSON. Каждая модель работала в своей папке
`artifacts/model-audit/<провайдер>--<модель>/` с копией исходных файлов. Claude и Codex запускались с уровнем
рассуждений high; у Antigravity уровень зашит в название модели, у Cursor уровень не передаётся.

1. **Код.** Исправить функцию объединения бронирований по спецификации в комментарии. Видимые тесты покрывают
   часть спецификации, 10 скрытых — всю: неизменность входа, вложенные интервалы, некорректные брони, сортировку
   «оператором <» и т. д. Кто чинит только до зелёных видимых тестов, набирает около 7 из 10.
2. **Ревью.** Файл на 46 строк с четырьмя настоящими ошибками (пагинация, обход проверки пути через соседнюю
   папку, потеря итоговых счётчиков, остановка записи после сбоя) и редкой гонкой как бонус. Там же — код, который
   выглядит подозрительно, но верен. За каждую ложную находку −0,5; явно ложных не было ни у кого, пограничные
   (нестрогий `parseInt`, символьные ссылки) не штрафовались.
3. **Логика.** Шесть сервисов, шесть дней, шесть условий: единственный порядок и число порядков без одного условия.
   Ответ проверен полным перебором.
4. **Репозиторий Orbit.** Два вопроса по коду (лимит перезапусков, паузы бесконечного улучшения) и ловушка:
   вопрос о несуществующей функции пересчёта токенов в доллары. Ловушку распознали все ответившие.
5. **Текст на русском.** Пересказать технический список изменений для не-программиста: не больше 60 слов,
   на «вы», без английских слов и названий программ, все четыре факта.

Время — активная работа агента. Десять агентов работали одновременно на одной машине, условия у всех одинаковые.

## Ограничения

- По одному прогону на модель (Sonnet 5.5 — три, Sonnet 4.6 — два). Разброс между прогонами одной модели заметен.
- Для флагманов задание оказалось лёгким: девять моделей набрали 96,9 и выше. Среди них выбирать стоит по скорости,
  квоте и манере, а не по баллам. Чтобы развести флагманов, нужен второй раунд посложнее: задача на несколько
  файлов и длинный контекст.
- Оценка русского текста частично субъективна. Вычеты расписаны выше, ключ лежит в наборе для повтора.

## Что аудит показал про сам Orbit

1. **Antigravity отдаёт все промежуточные сообщения как итог.** Ответ Claude 4.6 через Antigravity — 17–28 тыс.
   символов вместо 2–3 тыс. Разборщик берёт поле ответа CLI, а там склеены все сообщения хода. Стоит брать только
   последнее сообщение. *Исправлено 2026-09-30:* итог хода — последнее сообщение, если ответ CLI им заканчивается
   (`createSessionParser`). На записях аудита Opus 4.6 — 4,0 тыс. символов вместо 19,5 тыс.
2. **Переключение подписки не видно вызывающему.** `wait_agent` не сообщает, какая модель ответила на самом деле.
   Здесь три «агента Cursor» молча ответили как Sonnet 4.6 и 5.5; узнать это можно только из записи запуска.
   Стоит добавить в результат фактические провайдер и модель. *Исправлено 2026-09-30:* `wait_agent` и `list_agents`
   показывают провайдера, модель и `ranOn`, `model_evaluate` при нескольких моделях требует `model`.
3. **Зависший агент Antigravity не останавливается сам.** GPT-OSS 7 минут не присылал событий, остановили вручную.
   Нужен сторож бездействия для сессий Antigravity. *Исправлено 2026-09-30:* по записи запуска ход GPT-OSS закончился
   сам через 7 минут фразой «I'm sorry about the error…», а «стоп» дошёл до модели следующим ходом. Прежний тайм-аут
   процесса (15 минут без вывода) сработал бы позже, и агент после него просто падал. Теперь сторож хода
   (`electron/runtime/watchdog.mts`) останавливает ход у любого провайдера после 10 минут без событий, если не идёт
   команда, вызов инструмента Orbit или запрос разрешения. Остановленный ход повторяется на той же модели в новой сессии,
   при повторном молчании агент уходит на другую подписку.
4. **Устаревшая запись в памяти.** Оценка от 2026-09-29 «Gemini заблокирован по региону» больше не верна. Новые
   оценки моделей сохранены; старую запись можно удалить в панели памяти (агенту это запрещено).
5. **Ранги моделей по названию** (`electron/model-tiers.json`, для замены при исчерпании квоты) расходятся с
   замером: GPT-6 Luna по названию «лёгкая», а работает на уровне флагманов; Haiku 4.5 заметно слабее остальных
   «лёгких». *Исправлено 2026-09-30:* первые правила файла взяты из замера и называют причину. GPT-6 Luna — «сильная»
   (заменяет Sonnet и другие сильные модели, но не флагманов: русский текст у неё слабый). Haiku 4.5 и псевдоним
   `haiku` (пока он указывает на 4.5) — новый уровень «слабая»: заменяют только слабые модели или, если разрешены
   более слабые, лёгкие. GPT-OSS
   120B, который завис и не ответил, берётся только из пула, как неизвестная модель.

## Как повторить

Набор лежит вне репозитория, чтобы ключ не нашёлся поиском по коду при следующем аудите:
`%APPDATA%\orbit-ide\model-audit-kit\`. Там задание (`PROMPT.txt`), исходные файлы (`template/`), скрытые тесты,
эталон, проверка перебором, скрипты оценки и ключ (`ANSWER-KEY.md`). Порядок: создать папки
`artifacts/model-audit/<провайдер>--<модель>/` из `template/`, запустить агентов с `PROMPT.txt` (подставив папку),
затем `node grade.cjs <запись запуска> <репозиторий>`, `node extract.cjs <запись запуска>` и `node scores.cjs`.
Запись запуска — `%APPDATA%\orbit-ide\run-history\<runId>.json`. Перед оценкой проверьте в записи поле `handovers`
у агентов: при переключении подписки ответ дала другая модель.
