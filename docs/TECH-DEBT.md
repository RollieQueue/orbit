# Технический долг Orbit (после 0.4.0)

Пять пунктов, записанных после 0.4.0, выполнены 2026-09-30 (версия 0.4.3). Ниже — что сделано (подробности в указанных документах)
и что осталось. Порядок оставшегося — по важности для владельца.

## Сделано

1. **Перезапуск с продолжением задачи.** Корневой агент чата, который работает в репозитории Orbit, вызывает
   `restart_orbit { reason, continueWith, verify }`: проверки, сборка, перезапуск только изменившейся части Orbit;
   запуск завершается статусом `restarting`, а новый runtime сам продолжает задачу в том же чате, по возможности в
   прежней сессии провайдера. README, «Самообновление»; `docs/ARCHITECTURE.md`, «Process model and restarts».
2. **Runtime в дочернем процессе.** Главный процесс — только оболочка (окно, диалоги, отчёты здоровья, перезапуски),
   агенты, хранилища и провайдеры работают в отдельном процессе (`utilityProcess`). Три уровня перезапуска: окно,
   runtime, всё приложение; runtime перезапускается без закрытия окна примерно за 0,4 с (замер на машине владельца).
   `docs/ARCHITECTURE.md`, `docs/TYPESCRIPT-MAIN.md`.
3. **Типизация runtime.** Ни одного `// @ts-nocheck`, новых `any` нет, `tsconfig.main.json` включает
   `verbatimModuleSyntax`; что поведение не изменилось, проверено `scripts/check-type-equivalence.mjs`.
   `docs/TYPESCRIPT-MAIN.md`, «Typing completed».
4. **Сессионный режим Cursor и Antigravity.** Только в Full access: у Antigravity включён по умолчанию и проверен
   вживую, у Cursor включается вручную. `docs/SESSION-MODE.md`, `docs/providers.md`.
5. **Мелочи.** В `src/ChangesTab.tsx` нет строк длиннее 160 символов (только форматирование). 54 старые папки
   `Orbit-standalone-*` и `release*` (22,3 ГБ) удалены с согласия владельца, оставлена новейшая
   `Orbit-standalone-v1790694167819`. `runGit` (`electron/git.mts`) передаёт `GIT_CEILING_DIRECTORIES=<домашняя папка>`,
   и git в обычной папке под домашней (которая сама репозиторий) больше не видит «чужой» репозиторий. Устаревшая база
   отката `refs/orbit/self-upgrade/last-good` (кандидат от 2026-09-29 поверх 0.3.1.3) перенесена на проверенный снимок
   типизации, прежнее значение сохранено как `refs/orbit/self-upgrade/last-good-stale-20260929`; постоянное решение —
   запись работающего кода (`--record-running`, README, «Самообновление»).

## Что осталось

1. **Сессия Cursor включается только вручную** (`transport: 'session'` в настройках провайдера Cursor — переключателя
   в интерфейсе нет — или `ORBIT_CURSOR_SESSION=1`). Причина: у аккаунта Cursor исчерпана квота, и путь «модель →
   вызов инструмента Orbit по MCP» вживую не проверен; аргументы, плагин и разбор потока проверены только на
   поддельном CLI в тестах. Что сделать: в Full access с `ORBIT_CURSOR_SESSION=1` дать задачу, которая вызывает
   инструмент Orbit, и при успехе включить сессию по умолчанию в `providers.transportFor`.
2. **Ограниченные режимы Cursor и Antigravity в сессии не сделаны.** Без интерактивного подтверждения ни один из двух
   CLI не может разрешить вызов MCP, кроме как разрешив всё (`--force`, `--dangerously-skip-permissions`; у Cursor
   `--approve-mcps` к тому же одобряет все его настроенные MCP-серверы, не только сервер Orbit), поэтому в Ask, режиме
   чтения и работе с проектом они остаются на конверте. Нужен список разрешённого: собственный `CURSOR_CONFIG_DIR`
   Orbit со списком для Cursor и правило разрешения для `agy`.
3. **Нативные инструменты чтения для Antigravity в режиме конверта не сделаны.** Временный агент по-прежнему
   объявлен с `tools: []`, и каждое чтение файла — ход модели. Синтаксис заголовка агента, разрешающего инструменты
   чтения, нельзя проверить без живого вызова.
4. **Дочерний процесс runtime в собранном дистрибутиве не проверен.** Запуск точки входа из `app.asar` через
   `utilityProcess.fork` никто не проверял, поэтому собранная версия по умолчанию работает в режиме `inprocess`:
   runtime внутри главного процесса, новый код runtime загружает только полный перезапуск.
5. **Правка и runtime, и интерфейса стоит полного перезапуска.** Перезапуск runtime оставляет окно со старой сборкой,
   поэтому скрипт выбирает `full`. Можно заменить на перезапуск runtime плюс перезагрузку окна.
6. **`restart_orbit` отказывает, пока работают запуски других чатов** (агенту предлагается подождать и повторить), а
   пока работает сам скрипт, новые запуски в других чатах отклоняются. Возможный следующий шаг — перезапуск с
   автоматическим продолжением и этих запусков.
7. **Падение главного процесса завершает runtime без сохранения.** Под `utilityProcess` Chromium сразу (около 50 мс,
   замер) завершает дочерний процесс вместе с главным: запуски не останавливаются, хранилища не сбрасываются на диск;
   остаётся то, что было записано раньше. Мягкое завершение при пропаже родителя работает только у
   `child_process.fork` (тесты).
8. **Повтор долгого вызова по MCP не видит одной правки.** Результат вызова, припаркованного из-за предела
   MCP-клиента (Cursor), не отдаётся повторно, если после его начала менялись файлы (запись через Orbit, нативная
   правка, изменения, приписанные другой команде). Исключение: нативная правка, сделанная, пока припаркованная команда
   ещё работала, не замечается, если повтор приходит уже после её завершения, — агент получает прежний результат.
9. **Ожидание отчёта здоровья на уровнях `runtime` и `renderer` принимает любой свежий отчёт.** Если из одного
   репозитория запущены два экземпляра Orbit (два профиля), они пишут один файл здоровья, и отчёт другого экземпляра
   может быть принят за результат перезапуска.
10. **Откат уровня `full` останавливает все экземпляры Orbit этого репозитория**, а не только перезапускаемый.
11. **Во время отката уровня `runtime` вызовы окна отклоняются.** Примерно 0,7 с между неудачным стартом и сигналом
    наблюдателя runtime в состоянии `stopped`, и `runtime-client.cjs` сразу отклоняет вызовы (в журнале main:
    «Orbit runtime is stopped: …»); в интерфейсе ничего не видно. Можно ставить вызовы в очередь, пока ожидается
    перезапуск от self-upgrade.
12. **После Stop во время `restart_orbit` в `artifacts/self-upgrade-last.json` остаётся отчёт прошлого запуска.**
    Убитый скрипт не успевает записать отчёт `cancelled`; хост только завершает вызов.
13. **Карточка запуска после отката по-прежнему говорит «Агент перезапустил Orbit: …»** прямо под заметкой об откате;
    стоит показывать исход (`откатился`).
14. **Сделано 2026-09-30: сообщение работающему агенту прерывает идущий ход.** Ваше сообщение и сообщение
    руководителя помощнику приходят в конце ближайшего результата инструмента Orbit, а если агент работает только
    своими инструментами, Orbit через 2 секунды прерывает ход между шагами (не посреди команды) и продолжает ту же
    сессию с сообщением (`docs/CHANGELOG.md`, «Не выпущено»). Ввод в stdin CLI (`--input-format stream-json`,
    `turn/steer` App Server) не понадобился: прерывание одинаково работает у всех провайдеров. Осталось: прерванный
    первый ход Codex, Cursor и Antigravity начинается в новой сессии, потому что id своей сессии эти CLI сообщают
    Orbit только в итоге хода.
15. **Сообщение пользователя может остаться необработанным, если ход после ответа не удался.** Агент с готовым
    черновиком ответа получает ещё один ход ради сообщения; если провайдер падает без восстановления, отдаётся черновик,
    а сообщение остаётся «Доставлено» без ответа на него. Стоит дописывать к ответу, что сообщение не обработано.
16. **Метки `[orbit] MESSAGE FROM THE USER` и `[orbit] MESSAGE FROM YOUR SUPERVISOR` — обычный текст.** Вывод нативного инструмента (например, прочитанный файл)
    с той же строкой модель может принять за слова пользователя. Можно добавить к метке секрет сессии.
17. **Бесконечное улучшение: правка кода Orbit командой оболочки не требует `restart_orbit`.** Проверка ответа
    (`electron/runtime/improvement.mts`) видит только записи из `fileActivity`, то есть инструменты Orbit и нативные
    правки Claude и Codex. Правку через `sed`, heredoc или `git apply` в нативной оболочке она не видит, как и команду
    `run_command`, приписать которую не удалось. Такой ответ принимается без перезапуска, и изменение ставится только
    перезапуском следующей задачи. Надёжнее сравнивать отпечатки файлов на диске с отпечатками работающего экземпляра
    (`self-upgrade-health.json`).
18. **Сделано 2026-09-30: отказ старта следующей задачи, пока Orbit занят, повторяется через секунды.** Отказы
    `START_REFUSALS` (`electron/runtime/lifecycle.mts`) цикл повторяет через 5, 10 и 30 секунд без предупреждения и
    неудачей не считает (`docs/CHANGELOG.md`, «Не выпущено»).
19. **Бесконечное улучшение: мелкие неточности.** Три из четырёх исправлены 2026-09-30 (`docs/CHANGELOG.md`, «Не
    выпущено»): отклонённый старт больше не превращает итог прошлой задачи в «не закрыла ни одной задачи плана»,
    старая закрытая задача сохраняет название, паузу ставит только причина из текущего запуска. Осталось:
    - После отката своей правки агента всё равно просят вызвать `restart_orbit` (решается вместе с пунктом 17).
20. **Пауза и остановка агентов: мелкие неточности** (ревью и проверка в окне 2026-09-30).
    - Подагенты остановленного помощника показывают общее «Run cancelled» вместо «Остановлен вместе с
      руководителем»: `executeAgent` перезаписывает подпись, которую поставил `cancelDescendants`.
    - Если сессию после паузы не удалось возобновить, запись о паузе попадает в запрос новой сессии дважды.
    - Остановка помощника не будит руководителя, который ждёт в `wait_message`: он узнаёт об остановке, когда ожидание
      кончится. `wait_agent` просыпается сразу. В проверке окна это стоило 12 с.
    - Ход, прерванный паузой, засчитывается в лимит ходов помощника.
    - Точки состояния в панели квот и в истории запусков показывают паузу, только когда агент дошёл до ожидания, а не
      сразу после нажатия.
21. **Сделано 2026-09-30: `model_evaluate` оценивает модель, которая сделала работу.** Раньше оценка доставалась
    модели, на которой агент закончил после смены подписки: работа GPT-6 Astra сохранилась как оценка Gemini
    (`model-cc65e779…`, эту запись удаляет пользователь в панели памяти). Теперь `wait_agent` и `list_agents` показывают
    `ranOn`, а `model_evaluate` при нескольких моделях требует аргумент `model` (`docs/CHANGELOG.md`, «Не выпущено»).

## Живая проверка restart_orbit

Приёмка прошла на изолированной копии репозитория с настоящим Claude (haiku), 4 запуска, до раунда исправлений:

- A — перезапуск уровня `runtime` с продолжением в том же чате: от вызова инструмента до сигнала 1,3 с, новый
  runtime готов через 220 мс после запуска процесса, от готовности до начала продолжения 0,23 с, pid окна не
  изменился.
- B — синтаксическая ошибка: откат `electron/` (без файлов оболочки) из записи работающего кода, в чате заметка об
  откате, продолжения нет; от сигнала до восстановления 3,4 с.
- C — `verify: true` с ошибкой типов: инструмент вернул ошибку с выводом `tsc`, ничего не перезапускалось.

Найденное при этом исправлено: продолжение прежней сессии, когда `restart_orbit` вызван в первом ходе корневого
агента; остановка runtime для перезапуска ждала 2 с сам вызов `restart_orbit`; автоматический перезапуск упавшего
runtime соревновался с откатом (теперь запуск, упавший до готовности, сам не повторяется); `edit_file` в файлах с
CRLF. Корневой агент повторяет проверку после исправлений.

Повторная проверка после исправлений (свежая копия, 4 запуска haiku, сценарий D без модели): все четыре сценария
прошли. A — продолжение возобновило прежнюю сессию Claude (`--resume` с тем же id), от сигнала до готовности runtime
1,06 с (было 2,6 с), в тексте продолжения назван снимок; B — откат за 2,0 с (было 3,4 с), без гонки с
автоматическим перезапуском, индекс git копии не тронут; C — ошибка типов вернулась агенту за 3 с, перезапуска нет;
D — Stop во время тестов: маркер отмены записан, дерево скрипта и все процессы тестов убиты, блокировка снята,
ничего не перезапущено. Найденное при этом — пункты 11–13 выше.
