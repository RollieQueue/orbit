# Session mode: design contract (2026-09-29)

This document is the contract for the refactoring wave that replaces Orbit's
"kill the CLI at every tool envelope and respawn it with the whole transcript"
protocol. It is binding for everyone editing the code in this wave; update it
when a decision changes.

## Why (measured, not guessed)

From the 44 saved runs in `%APPDATA%\orbit-ide\run-history`:

- Every Orbit tool call (`memory_save`, `wait_agent`, `send_message`, `spawn_agent`, …)
  ended the CLI process and started a new one with the transcript re-sent
  (20–135 K chars). Cost per boundary: 26–189 s, then the model re-verified
  everything it had already seen (3.5 min of repeated checks after one
  `memory_search`).
- After the final answer the harness forced 1–3 more cold turns (model_evaluate
  reminders ×3, skill reminder, "messages arrived"). One of them rewrote
  `discussion.md`.
- Process start is not the cost (`claude.exe --version` 36–125 ms). Time to
  first token on a big cold prompt is.
- Antigravity runs with `tools: []`, so every file read is a 200-line page turn.
- Codex root agents polled `list_agents`/`read_messages`/`context_read` up to
  71 turns in a row; the loop guard cannot see it because each answer differs.

Owner's invariants (do not trade these away):

1. Model strength stays: no forced effort downgrade, no `--max-turns` by default,
   no cap on what a model may do inside its native loop.
2. Memory, skills (self-improvement), swarm delegation, team messaging, quota
   failover and the agent inspector keep working and stay observable.
3. No cold starts caused by Orbit itself. Memory is cross-run knowledge, not a
   substitute for session continuity.

## Transports

| Provider | Transport | Continuation | Orbit tools |
|---|---|---|---|
| claude | `session` | `--resume <id>` | MCP (HTTP, in-process) |
| codex (exec) | `session` | `codex exec resume <id>` | MCP via `-c mcp_servers.orbit.*` |
| codex (app-server, Ask mode) | `session` | same thread, `turn/start` per turn | MCP via config overrides |
| cursor, antigravity | `envelope` (unchanged) | — | JSON envelope |
| ollama, custom endpoint | `envelope` (unchanged) | — | JSON envelope |

`providers.transportFor(providerId, options)` returns `'session'` or `'envelope'`.
`ORBIT_LEGACY_ENVELOPE=1` forces envelope mode for every provider (escape hatch).

### Claude session invocation

```
claude --print --output-format stream-json --verbose --include-partial-messages
       --session-id <uuid generated by Orbit>            (first turn)
       --resume <that uuid>                              (follow-up turns)
       --mcp-config '<inline JSON>' --strict-mcp-config
       --allowedTools mcp__orbit__*  [--tools Read,Glob,Grep in restricted modes]
       --append-system-prompt-file <tmp file with the stable Orbit block>
       --permission-prompt-tool mcp__orbit__approve      (Ask mode only)
       --permission-mode default|bypassPermissions --effort <level> --model <m>
```

Prompt on stdin. **No `--no-session-persistence`** (resume needs the session file).
The MCP config: `{"mcpServers":{"orbit":{"type":"http","url":"http://127.0.0.1:<port>/mcp","headers":{"Authorization":"Bearer <token>"}}}}`.
The session id comes back in the `system/init` and `result` events; Orbit already
chose it, so it is known before the process starts.

### Codex session invocation

`codex exec --json --skip-git-repo-check -C <ws> --sandbox <mode> -c features.multi_agent=false
 -c 'mcp_servers.orbit.url="http://127.0.0.1:<port>/mcp"' -c 'mcp_servers.orbit.bearer_token_env_var="ORBIT_MCP_TOKEN"' … -`
with `ORBIT_MCP_TOKEN` in the child environment. **No `--ephemeral`.** The thread id
comes from the `thread.started` JSON event; follow-ups use `codex exec resume <id> -`.
The App Server transport keeps its thread alive for the agent's life and sends one
`turn/start` per Orbit turn. No process is killed at a tool call any more; the
`TOOL_HANDOFF` path stays only for envelope providers.

### Timeouts

`runCli` gets `inactivityMs` (default 15 min, env `ORBIT_PROVIDER_INACTIVITY_MS`):

Session processes also get `NO_PROXY`/`no_proxy` with `127.0.0.1,localhost,::1` appended (`providers.loopbackNoProxy`):
with `HTTP_PROXY` set, Claude Code otherwise reports the loopback MCP server as `failed` (found in the first live check).
the process is killed only when it emits nothing for that long. The old 30-minute
total deadline applies only when `run.limits.timeoutMs` is set explicitly.

## MCP server (`electron/mcp-server.cjs`, new)

- One in-process streamable-HTTP MCP server per app, `127.0.0.1`, ephemeral port,
  started lazily on the first session. Built on `@modelcontextprotocol/sdk`
  (`server/index.js` low-level `Server` + `server/streamableHttp.js`).
- Auth: `Authorization: Bearer <token>`; the token identifies one (run, agent).
  `mcp.issueToken({ runId, agentId })` / `mcp.revoke(token)`; unknown token → 401.
- `tools/list` comes from `electron/tool-registry.cjs` (new, see below), filtered by
  the agent's role (root-only tools) and access mode (no write tools in read-only).
- `tools/call` → `dispatch(token, name, args)` → `runtime.executeTool(run, agent, name, args)`.
  Result: `content: [{type:'text', text: <observation JSON as the envelope path produces>}]`.
  If the agent has unread mail after the call, append `\n[orbit] unread messages: N. Call read_messages.`
  Errors → `isError: true` with the message; never throw across the HTTP boundary.
- Waiting tools (`wait_agent`, `wait_message`, `followup_agent`) release the agent's
  model slot before blocking and re-acquire it afterwards (`runtime.releaseTurn` / `acquireTurn`).
- `approve` tool (for `--permission-prompt-tool`): input `{tool_name, input, tool_use_id}`;
  output text is a JSON string `{"behavior":"allow"|"deny","updatedInput"?:…,"message"?:…}`.
  It calls `runtime.approve(run, agent, request)`.

### `electron/tool-registry.cjs` (new)

Single source of truth for every Orbit tool:

```js
module.exports.TOOLS = [{
  name: 'spawn_agent', description: '…', inputSchema: { type:'object', properties:{…}, required:[…] },
  rootOnly: false, waits: false, mutating: true, minAccess: 'read-only'|'workspace-write'|'danger-full-access'
}, …]
module.exports.describeForPrompt = (agent, run) => string   // the text the envelope prompt used to embed
module.exports.validate = (name, args) => { ok, error }      // replaces the inline checks in executeTool
```

Descriptions are the current prompt texts from `runtime.cjs` (the `spawn_agent {…}` lines),
moved verbatim. The envelope prompt is rebuilt from `describeForPrompt` so envelope
providers see the same text as before.

## Runtime (`electron/runtime.cjs`)

`agent.transport` is decided at `createAgent` from the provider. The envelope loop is
the existing `executeAgent`. The session loop:

1. Build `systemAppend` (stable: identity, access rules, delegation rules, memory/skill
   etiquette, "how Orbit tools differ from native tools"; ≤ 6 000 chars; nothing
   volatile) and `userPrompt` (the task plus everything `context()` produces today:
   memory block, skills, shared context, index overview, chat digest, team roster,
   FILE MAP). Session mode sends no `ORBIT_RESPONSE_SCHEMA` and no envelope guide.
2. `runProvider({ …, session: { id, token, mcpUrl, systemAppend, resume: false }, prompt })`.
   Stream events as today (`providerEvent`), including MCP tool calls which Claude
   reports as `mcp__orbit__<name>` tool events. Every Orbit tool call made through
   MCP is recorded in the ledger/work log exactly as an envelope call would be.
3. The returned text is the answer candidate. Post-answer checks, in this order,
   each at most once per candidate: (a) children still running or results not yet
   seen → wait as today, then `resume` with "these helpers finished: …"; (b) unread
   mail → `resume` with "messages arrived: …"; (c) completed workers not evaluated →
   ONE combined `model_evaluate` reminder (not three); (d) improvement mode not
   completed → the existing continuation; (e) skill learning → the existing single
   reminder. Each resume is `runProvider({ session: { resume: true, id }, prompt: instruction })`.
   A resume that fails delivers the candidate (`draftAnswer` logic stays).
4. Handover (quota/failure) works as today: the note is built from the ledger; the
   replacement provider starts a fresh session with the note in its user prompt.
5. Cancellation kills the process tree as today.

Also in this wave (runtime): per-turn timing records
`agent.turnTimings[] = { turn, transport, startedAt, firstEventAt, endedAt, promptChars, nativeToolCalls, orbitToolCalls, sessionId }`
persisted with the run; trace cap 400 → 2 000; `JSON.stringify(transcript)` in the
trim loop replaced by tracked lengths; snapshot cloning only when persisting;
`message.streaming` events (`{ runId, chatId, agentId, messageId, content }`,
≤ 4/s) for the root agent's partial text and a final `message.added` with the same
`messageId`; envelope-mode poll budget: six consecutive turns that only called
`list_agents` / `read_messages` / `context_read` / `wait_*` add one nudge to use
`wait_agent` with a timeout; nothing is stopped.

## Self-upgrade (`scripts/self-upgrade.cjs`, `electron/main.cjs`, `Orbit.cmd`)

The app runs from the repository directory. `Orbit.cmd` starts
`node_modules\electron\dist\electron.exe <repo>` (with `ELECTRON_RUN_AS_NODE` cleared).
`npm run self-upgrade` becomes: typecheck → tests → runtime smoke → `main-load` test →
`vite build` → ask the running Orbit to relaunch (`Orbit.cmd --relaunch` hits the
`second-instance` handler, or the `app:relaunch` IPC) → wait ≤ 15 s for
`artifacts/self-upgrade-health.json` written by the new process after
`did-finish-load` and one IPC round trip → on failure restore `dist-prev/` and the
last good git tree for `electron/`+`src/` and relaunch again. No electron-builder,
no `Orbit-standalone-*` copy.
The relaunch phase runs in a detached watcher (survives the agent's command tree being stopped by the relaunch).
`last-good` is recorded only after a healthy start; the failed tree is kept as `refs/orbit/self-upgrade/failed`.
No `--loop` handoff any more; the cycle cap is ORBIT_UPGRADE_MAX_CYCLES relaunches per ORBIT_UPGRADE_CYCLE_WINDOW_MIN minutes. `npm run package:win` stays as an explicit
distribution step. `run_command` default timeout 600 s, clamp 20 ms–3 600 s.
Old bundles are not deleted by code; `npm run clean:bundles` lists and removes them
on request.

## IPC contract (`electron/ipc-contract.cjs`)

One table of every renderer-callable method: `{ method, channel, args: [{ name, type, optional? }], returns, push? }`
(`CALLS`), plus the two push events `runtime:event` and `quota:update` (`EVENTS`). Type strings are TypeScript as the
renderer sees it (`GitContext`, `RuntimeEvent`, … from `vite-env.d.ts`, or `import('./types').X`).

- `electron/preload.cjs` and the block between the `BEGIN/END generated` markers of `src/vite-env.d.ts` (`OrbitBridge`,
  `Window.orbit`, `StartTaskPayload`, `QuotaUpdate`, …) are written by `node scripts/gen-ipc-types.cjs` (`--check` only
  reports). The preload cannot `require` the contract (Electron's renderer sandbox), so its table is inlined.
  `tests/ipc-contract.test.cjs` fails when either file drifts. `GitContext`, `ProjectIndexStatus`, `ProviderHealth`
  and `RuntimeEvent` stay hand-written outside the markers.
- `electron/ipc-handlers.cjs` implements the call channels as a `Map` keyed by channel; `registerIpcHandlers` throws at
  start-up when a contract channel has no handler or a handler has no contract entry. `main.cjs` is lifecycle + wiring.
- To add a method: one entry in the contract, one `handle('…')` in `ipc-handlers.cjs`, run the generator, use it in `src/`.
- Removed in wave 2 as unused by the renderer: `routeMessage` (stub), `spawnSubAgent`, `getProjectContext`,
  `searchMemory`, `platform`. Kept although unused by `src/`: `inspectWorkspace`, `getRun` (typed), `applyArtifact`
  (only path into `worktree.cjs`), `ping`/`relaunch` (health check and self-upgrade).
